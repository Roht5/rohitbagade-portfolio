About

My journey into software engineering started with a simple fascination: building things that people could interact with in real time. In the beginning, that meant crafting fluid interfaces with Flutter—focusing on animations, layout structures, and single-threaded event loops. I loved the visual feedback of making things look and feel smooth.

But as I built more complex applications, I realized that the user experience is only as fast as the engine running behind it. A gorgeous UI doesn't mean much if the database query behind it times out. That curiosity led me to dive deep into backend architecture, moving from mobile layouts to the world of .NET, SQL Server, and distributed event streams.

Today, at Zenoti, my day-to-day is about learning how systems handle real-world pressure. I've spent my time figuring out how to build microservices that don't fall over under load. I've learned that a query running in seconds on a local machine can easily drag down production for minutes if you don't understand execution plans and indexing. I've watched pipelines struggle with bulk data ingestion, which pushed me to design resilient, non-blocking Kafka streams with DLQ safeguards to keep the main pipeline moving.

For me, programming is less about selling solutions and more about solving puzzles. Whether it's optimization, collaborating with teams on system design, or turning hackathon ideas into actual product tools, I enjoy the quiet process of making complex systems a little more robust and a little more predictable.

Outside of work, I built Notifyx — a multi-tenant notification service in Go — to get hands-on with Kafka consumer design, rate limiting, and idempotency outside the constraints of a single stack.
