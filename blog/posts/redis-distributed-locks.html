Implementing Distributed Lock Patterns with Redis in C#

Published on November 12, 2025 · 4 min read · 1,240 views

In a distributed backend ecosystem, preventing multiple concurrent operations from modifying the same resource is one of the most common challenges. While in-memory locks like lock or SemaphoreSlim work perfectly within a single process, they fall short when scaling your application across multiple containers.

This is where a centralized distributed locking mechanism becomes necessary. Using Redis and the Redlock algorithm, we can safely coordinate access across distributed nodes in a high-throughput .NET Core microservices architecture.

The Basic Concept: SET with NX and PX

At its core, a Redis distributed lock relies on the atomic SET command with NX (set if not exists) and PX (set expire time in milliseconds) options. 

// Simple lock acquisition
var db = redis.GetDatabase();
string lockKey = "resource:order:12345";
string token = Guid.NewGuid().ToString();
TimeSpan expiry = TimeSpan.FromSeconds(30);

bool acquired = db.StringSet(lockKey, token, expiry, When.NotExists);

By storing a unique token, we ensure that a node can only release the lock if it owns the token. This prevents a node from accidentally releasing a lock acquired by another process that took longer to execute.

Releasing Safely with Lua Scripts

To release the lock atomically, we check if the key's value matches our token before deleting it. This requires executing a small Lua script: 

string luaRelease = @"
    if redis.call('get', KEYS[1]) == ARGV[1] then
        return redis.call('del', KEYS[1])
    else
        return 0
    end";

var result = db.ScriptEvaluate(luaRelease, 
    new RedisKey[] { lockKey }, 
    new RedisValue[] { token });

This pattern guarantees that the check-and-delete steps happen as a single atomic operation inside Redis, ensuring system safety and data consistency.
