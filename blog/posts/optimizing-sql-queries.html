Optimizing SQL Query Execution Times from Minutes to Seconds

Published on May 15, 2026 · 4 min read · 980 views

Slow SQL queries are the silent killers of backend service performance. As database tables grow, queries that initially took milliseconds begin to crawl, taking minutes to complete.

Recently, we encountered a reporting query at Zenoti that took nearly 3 minutes to return aggregate lead conversion data. Here is the process we used to reduce that query runtime to less than 5 seconds.

1. Analyzing the Execution Plan

The first step was running an EXPLAIN ANALYZE command on the query. This outputs the query planner's execution tree along with exact timings: 

EXPLAIN ANALYZE
SELECT lead_id, COUNT(action_id)
FROM lead_actions
WHERE created_at >= '2026-01-01'
GROUP BY lead_id;

The output showed a massive Sequential Scan (Seq Scan) across 15 million rows in the lead_actions table. The query planner was reading the entire table from disk because no appropriate index was available.

2. Introducing Composite Indexes

We created a composite B-Tree index on the columns used in the filter and grouping stages: 

CREATE INDEX idx_lead_actions_created_lead
ON lead_actions (created_at, lead_id);

This allowed the query planner to switch to an Index Only Scan, bypassing raw table blocks and reading aggregated statistics directly from the index blocks in memory.

3. Results

Execution time dropped from **178 seconds to 4.2 seconds**. The database CPU load decreased by 40% during peak report generation hours.
